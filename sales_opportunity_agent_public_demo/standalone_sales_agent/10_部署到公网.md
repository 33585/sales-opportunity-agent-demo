# 把销售商机上报 Agent 部署成公开链接

你要给面试官或外部人员直接打开使用，必须部署到公网。仅仅把程序复制到另一台电脑，只能让那台电脑本地使用，别人无法通过链接访问。

## 推荐方式：GitHub + Render

这个项目已经准备好 Render 配置：

- 根目录的 `render.yaml`
- `standalone_sales_agent/Dockerfile`
- 云端端口自动读取 `PORT`
- 云端监听 `0.0.0.0`
- 健康检查地址 `/health`

Render 会给 Web Service 分配一个 `onrender.com` HTTPS 地址。官方文档说明，Web Service 必须监听 `0.0.0.0`，并使用平台提供的 `PORT`；服务会获得公开 URL。免费 Web Service 长时间无访问后可能休眠，面试演示第一次打开可能需要等待几十秒。

## 第一步：准备 GitHub 仓库

把整个项目目录上传到一个 GitHub 仓库。建议仓库设置为 Private，只有你自己和部署平台可以访问。

至少要包含：

```text
agent.md
render.yaml
standalone_sales_agent/
```

不要把真实客户数据、CRM Token、密码、API Key 放进仓库。

## 第二步：在 Render 创建服务

1. 打开 https://render.com/ 并注册。
2. 使用 GitHub 登录。
3. 点击 `New`，选择 `Web Service`。
4. 选择刚才的 GitHub 仓库。
5. 如果页面没有自动读取 `render.yaml`，手动填写：
   - Runtime：`Python`
   - Build Command：`python3 -m py_compile standalone_sales_agent/app.py`
   - Start Command：`python3 standalone_sales_agent/app.py`
   - Health Check Path：`/health`
   - Region：选择离面试官较近的区域，例如 Singapore
6. 点击创建并等待部署完成。
7. Render 会显示一个类似下面的地址：

```text
https://sales-opportunity-agent-xxxx.onrender.com
```

这个就是可以发给面试官的演示链接。

## 第三步：发布前测试

浏览器依次打开：

```text
https://你的域名.onrender.com/
https://你的域名.onrender.com/health
```

`/health` 应返回：

```json
{"status": "ok", "service": "sales-opportunity-agent"}
```

然后点击“填入样例”，点击“生成商机草稿”，确认页面能展示客户需求、决策人、阶段、风险和下一步行动。

## 第四步：给面试官的演示方式

只发这个地址：

```text
https://你的域名.onrender.com
```

面试官不需要安装 Python，不需要打开终端，也不需要访问你的电脑。

推荐演示流程：

1. 点击“填入样例”。
2. 点击“生成商机草稿”。
3. 展示客户需求、决策人、商机阶段、风险和下一步行动。
4. 说明预算未确认会被标成风险。
5. 点击“确认提交到模拟 CRM”。
6. 展示返回的商机编号。

## 本地迁移备用方案

如果要把程序带到另一台 Mac：

1. 复制整个 `standalone_sales_agent` 文件夹。
2. 双击 `start_mac.command`。
3. 浏览器打开 `http://127.0.0.1:8787`。

如果是 Windows：

1. 复制整个 `standalone_sales_agent` 文件夹。
2. 双击 `start_windows.bat`。
3. 浏览器打开 `http://127.0.0.1:8787`。

这只是本地备用方案，外部人员不能直接访问这个本地地址。

## 重要限制

当前版本已经增加登录校验、角色权限、SQLite 数据库和操作审计。演示账号默认是：

```text
sales01 / Demo@123456
manager01 / Demo@123456
admin / Demo@123456
```

部署到公网时，在 Render 的 Environment Variables 中设置：

```text
DEMO_SALES_PASSWORD=你的销售演示密码
DEMO_MANAGER_PASSWORD=你的主管演示密码
DEMO_ADMIN_PASSWORD=你的管理员演示密码
COOKIE_SECURE=true
```

如果是第一次启动，这些密码会用于初始化账号。正式生产环境需要接入 PostgreSQL / MySQL、企业统一身份认证和真实 CRM API；SQLite 适合演示和小规模试点，不适合多实例生产部署。
